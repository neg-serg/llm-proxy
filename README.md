# llm-proxy

An OpenAI-compatible HTTP proxy that sits in front of
[llama-swap](https://github.com/mostlygeek/llama-swap) on the local model fleet.
`llama-swap` already swaps models and speaks the OpenAI API; this proxy adds the
three things a long agent chain needs and the server does not do:

- **keep the request inside the slot's context window.** `llama-server` answers
  400 when the prompt does not fit, and a long chain reaches that point
  silently. The proxy estimates the prompt size, trims old tool results and
  messages, and re-packs what is left so the single-system-message invariant
  holds.
- **normalize the tool-calling protocol quirk of small models.** They batch
  dependent calls and invent values they should have read, and they expect tool
  results as plain text carrying a `name`, not a JSON wrapper.
- **retry the swap race.** Switching models mid-flight yields 500 `group
  starting ... aborted` or 502 `proxy error: EOF`; the proxy unloads, waits and
  retries (`RETRY_DELAYS = 5, 10, 15` seconds).

Every guard is opt-in per model profile in the JSON config, so the proxy is a
transparent passthrough for anything not listed.

## Usage

```console
$ llm-proxy --config /etc/llm-proxy/config.json
llm-proxy listening on 127.0.0.1:9300 -> http://127.0.0.1:9292
```

The config is JSON; unset keys fall back to the defaults below:

```json
{
  "upstream": "http://127.0.0.1:9292",
  "host": "127.0.0.1",
  "port": 9300,
  "defaults": {
    "ctx": 32768,
    "reserve": 4096,
    "keep_tool_results": 6,
    "keep_last_messages": 8,
    "single_tool": false,
    "thinking": null,
    "target": null
  },
  "profiles": {
    "<model name as llama-swap reports it>": { "ctx": 131072, "reserve": 8192 }
  }
}
```

Token counts are estimated by character class rather than with a tokenizer, and
the constants are measured (baseline subtracted) on `qwen3.8` and `devstral` over
the same texts: English prose 4.7 chars/token, source code 3.6, Russian 2.9,
Russian technical prose 2.5, Chinese 1.2. A text whose script is a substantial
share is priced entirely at that script's rate — the pessimistic end, which can
trim a little early but never overflows the slot.

## Testing

Everything is stdlib; there is no test dependency and no network access:

```console
$ python3 -m unittest discover -s . -p 'test_*.py' -v
$ nix flake check -L      # the same suite, plus the packaged build
```

The suite covers the guards that are easy to break silently: the
single-system-message invariant, tool-result normalization, and the trimming
invariants.

## Where it runs

On the host it is the `llm-proxy` systemd service, started with a config
generated by the NixOS module (`/etc/nixos` → `modules/llm/proxy.nix`). The proxy
owns `/v1/*` chat traffic; management endpoints (`/unload`, `/running`) stay on
llama-swap, and `llmctl` falls back to llama-swap when the proxy is down.
